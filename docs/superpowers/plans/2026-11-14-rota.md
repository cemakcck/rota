# Rota Web (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Rota web app (phase 1 of the spec): accounts, shared trips with invites, places with categories from map search, ordered days with routes, Google Maps links, the five extras, live collaboration, offline PWA, and demo mode, deployable to Railway with a Neon Postgres. The mobile app (spec §13) gets its own plan once this one is done; this plan only sets up the shared package it will reuse.

**Architecture:** npm workspaces monorepo. `packages/trip` holds everything about a trip that is not UI or server (Yjs document model, fractional ordering, read-only view, undo, timeline, travel estimates, Google Maps links, opening-hours evaluation) with no DOM or React Native imports, so the Expo app reuses it. `apps/web` is Next.js 16 behind a custom one-port Node server that also mounts Hocuspocus at `/sync`; Postgres (Drizzle) stores accounts, trips, memberships, invites and Yjs document state. Browsers keep each trip in IndexedDB and edit locally; Hocuspocus relays updates and presence after checking membership.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind CSS 4, next-intl 4, Better Auth (email+password, bearer plugin), Drizzle ORM + PostgreSQL 17 (Neon in production), Yjs, y-indexeddb, @hocuspocus/server + @hocuspocus/provider, Tiptap (Collaboration, CollaborationCaret), MapLibre GL JS + OpenFreeMap, Photon, FOSSGIS OSRM, Overpass, Open-Meteo, `opening_hours`, `fractional-indexing`, @dnd-kit, Radix dialog, `qrcode`, Resend, Vitest, Playwright + @axe-core/playwright.

**Spec:** `docs/superpowers/specs/2026-11-14-rota-design.md` (revision 2). Read it before any task; the spec wins over this plan where they disagree.

## Global Constraints

- **Ports:** dev `3400`, Playwright `3401`, ad-hoc container check `3402`, local Postgres (docker compose) `5434`. **Never use ports 3000 or 3100.** Never touch `clinic-booking-db-1` (5433) or `lodos-mongo-1` (27018).
- Node 22. Next.js 16, React 19, Tailwind 4, next-intl 4, Vitest 5, Playwright 1.65, Better Auth 1.x, matching `~/Personal/clinic-booking` (use its `vitest.config.ts`, `playwright.config.ts`, `eslint.config.mjs`, `src/i18n/*`, `src/lib/auth/*`, email module and CI workflow as reference shapes). Other libraries: latest stable at install.
- **`packages/trip` imports only `yjs`, `fractional-indexing`, `opening_hours` and the standard library.** No DOM, React, Node-only or React Native APIs.
- **No paid APIs.** Upstreams (always via our server routes except tiles): tiles `https://tiles.openfreemap.org/styles/liberty`; search `https://photon.komoot.io/api/` and `/reverse`; routing `https://routing.openstreetmap.de/routed-foot/route/v1/driving/{coords}` (walk) and `…/routed-car/route/v1/driving/{coords}` (drive); opening hours `https://overpass-api.de/api/interpreter`; weather `https://api.open-meteo.com/v1/forecast`. Header `User-Agent: Rota portfolio demo (https://github.com/cemakcck/rota)`.
- **Hosting:** one Railway container + **Neon free Postgres** (~$5/month total). Every DB access goes through `withDbRetry` (Task 4). Railway health checks never touch the DB.
- **Languages:** English and Turkish, routes `/en`, `/tr`. All UI strings in `apps/web/messages/{en,tr}.json`; a test asserts identical key sets. Trip and place names are user data and never translated.
- **Accessibility:** WCAG 2.2 AA; every drag has a keyboard/button alternative; the itinerary list is the accessible source of truth for the map; respect `prefers-reduced-motion`. Light theme only.
- **Ids:** trip ids 128-bit random base62, exactly 22 chars; other ids 12-char base62.
- **Categories (exact, in this order):** `food, drinks, cafe, museum, sight, nightlife, shopping, nature, gym, stay, other`. Default stay minutes: food 75, drinks 60, cafe 45, museum 120, sight 45, nightlife 120, shopping 60, nature 90, gym 60, stay 0, other 60. Tags: ≤ 5 per place, ≤ 24 chars each, trimmed, case-insensitive unique.
- **Limits:** sign-ups and demo starts 20 per IP per day; 50 trips per user; 20 members per trip; 50 concurrent connections per trip; WebSocket message > 1 MB closes the connection; soft caps 2 MB document / 200 places / 100 checklist items enforced **in the interface only** (the server never refuses a member's update for size); proxy limits per IP per minute: search 60, routing 120, opening hours 60, weather 60; ≤ 1 upstream request per second per service. IPs stored only as HMAC-SHA256 with `IP_HASH_SECRET`.
- **Cleanup:** hourly in-process timer deletes demo users (and trips they own) with `last_active_at` older than **7 days**. Real accounts are never auto-deleted.
- **Tests run with `TZ=America/New_York`.** Dates are `YYYY-MM-DD` strings, times `HH:MM` strings; never instants.
- **Commits:** conventional messages, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01G1gUztbjonzCYopjxcu6K3`. Never push. Kill processes by PID, never `pkill -f`.

## Review Focus

1. **Two windows in one browser share cookies and localStorage.** "Try it with a friend" must be a different signed-in user in the second window. → Task 8 test `friend mode uses the sessionStorage bearer token, not the cookie` and Task 16 e2e `Try it with a friend opens a second window as Deniz`.
2. **Neon cold start.** The first query after idle can drop; sign-in, trip loading and document stores must retry, and an open trip keeps editing locally meanwhile. → Task 4 test `withDbRetry retries a dropped first connection`.
3. **A member removed (or a trip deleted) while their device is offline with edits.** On reconnect they must get the "removed"/"deleted" message, not a silent loss and not a write-through. → Task 6 test `a removed member's reconnect is refused with removed` and Task 8 test `removed reason shows the message and keeps edits until confirmed`.
4. **A remote delete lands while you are moving or editing that place.** No ghost row, no crash, no resurrection. → Task 2 test `moving a place someone deleted is a no-op` and Task 10 test `remote delete while the Move dialog is open closes it`.
5. **Turkish and odd input** (ı, ş, ğ, emoji, 120-char names, a tag with only spaces). → Task 13 test `search passes Turkish queries through intact`, Task 10 test `a 120-character Turkish place name wraps without overflow`, Task 2 test `tags are trimmed, deduplicated case-insensitively and capped at 5`.
