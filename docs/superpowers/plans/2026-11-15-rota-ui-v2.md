# Rota UI v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Rota trip screen around "one day at a time, details on demand" per the approved mockup, without changing any behaviour underneath.

**Architecture:** A single view state (`day | ideas | checklist | all`, mirrored in the URL) drives both the list column and the map. Stops render as compact rows; all per-place controls move into a details panel. Desktop is rail · list · map; phone is header + day chips + bottom tabs. Existing hooks (`useTrip`, presence, travel/hours/weather, undo, announcer) are reused unchanged.

**Tech Stack:** as today (Next.js 16, React 19, Tailwind 4, next-intl, @dnd-kit, Radix, MapLibre + OpenFreeMap, Vitest, Playwright + axe).

**Spec:** `docs/superpowers/specs/2026-11-15-rota-ui-v2-design.md` (and the base spec it extends). **Visual reference:** `docs/design-reference/rota-trip-v2.html` — match its hierarchy, spacing and feel.

## Global Constraints

- No behaviour change: every feature, permission, offline/sync rule and limit of the base spec stays; only layout/navigation/visuals change. Read-only while `userId` is null stays.
- EN + TR identical message keys; remove keys no longer used; trip/place names are user data.
- WCAG 2.2 AA: every drag has a keyboard/button alternative (Alt+↑/↓ on rows, Move to… in details); details panel is a labelled dialog/region that returns focus; list is the accessible source of truth for the map; polite announcer unchanged; reduced motion respected; axe scans must stay clean.
- Map style URL: `https://tiles.openfreemap.org/styles/positron`; the service worker's map-asset handling (stale-while-revalidate for style/TileJSON/glyphs/sprites, cache-first .pbf) must cover it.
- Fonts via next/font: Fraunces (titles), Inter (body). Light theme only.
- Ports: dev 3400, e2e 3401; never 3000/3100. Kill by PID only. Never push. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01G1gUztbjonzCYopjxcu6K3`.
- Every task ends with `npm run lint && npm run typecheck && npm test` green; Tasks 5–6 also `npm run test:e2e`.

## Review Focus

1. **Selected day deleted remotely** while viewing it → view falls back to the nearest remaining day (or Ideas), no crash, URL updated. → Task 1 test `view falls back when its day is removed remotely`.
2. **Details panel for a place deleted or moved remotely** → panel closes (deleted) or follows the place to its new day (moved), focus sane. → Task 3 tests.
3. **Drag a row onto a rail day / Ideas** with keyboard alternative → one move, announced, undoable. → Task 2 test `dropping on a rail day moves the place` and `Alt+ArrowDown reorders and announces`.
4. **Phone ↔ desktop resize** keeps the same view and selection. → Task 5 test.
5. **Long Turkish names and many stops (30)** → rows truncate cleanly with full name in title/aria, column scrolls, no horizontal overflow. → Task 2 test.

### Task 1b: Times you set yourself — model and timeline (spec §2b)

**Files:** `packages/trip/src/{schema,doc,view,timeline,seed}.ts`, tests in `packages/trip/test/`; `apps/web/src/client/useHours.ts` (and any caller of `dayTimeline` / `startTime`) adapted so the app keeps working until Tasks 2–3 add the UI.
**Interfaces:** `PlaceView.time: string | null` ("HH:MM"); `setPlaceTime(doc, placeId, time: string | null, origin)` — validates HH:MM (00:00–23:59), and when non-null moves the place's order to its chronological slot among the day's timed places (untimed neighbours keep relative order); `addPlace(…, { time?: string | null })` places a timed stop chronologically; `movePlace` keeps current behaviour and returns as before — the caller (UI) re-times via `suggestTime`; `suggestTime(day: DayView, legs, index: number): string | null` = previous stop's arrival + stay + travel, null if nothing timed before; `dayTimeline(day, legs)` returns per stop `{ placeId, arrive: string | null, leave: string | null, estimated: boolean, lateBy: number | null /* minutes */, overflowDays }` — set time → not estimated; untimed after a timed stop → estimated; untimed before any timed stop → null; lateBy when a set time is earlier than reachable. `day.startTime` no longer read; on `readTrip`, a legacy day whose first stop has no time but the day has `startTime` exposes that as the first stop's time? — no: migration is done once by `migrateDayStart(doc, origin)` (writes the first stop's time from startTime when that stop has none, then deletes startTime), called by the client when a trip loads.
**Tests (write first):** `a set time shows as arrive, not estimated`, `untimed stops after a timed one get estimated times including travel`, `untimed stops before any timed stop have no time`, `setting a time moves the stop into chronological order`, `untimed stops keep their position between timed neighbours`, `a set time earlier than reachable reports lateBy`, `suggestTime is previous end plus travel, null with nothing timed before`, `setPlaceTime rejects 24:00 and garbage`, `migrateDayStart moves startTime onto the first stop once`, `concurrent setPlaceTime on two peers converges with one copy`, `seed has timed and untimed stops`; update existing timeline/hours tests.
**Commit:** `feat(trip): times set per stop; no default day start`.
